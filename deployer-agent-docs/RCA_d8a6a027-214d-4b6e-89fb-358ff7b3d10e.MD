# RCA — adam-sandbox deploy failure

## Summary
The deploy cannot proceed for TWO independent reasons:

1. **Build failure (source):** `backend/requirements.txt` line 148 pins `torch==2.15.0+cpu`, which does not exist on the package index. `build_image` fails every attempt.
2. **Resume blocked (credits):** The re-trigger (`trigger_indie`) was refused with `insufficient_credits` — 49.50 available vs 50 required (non-retryable).

## Evidence

### 1. Invalid torch pin (build_image, step #39 backend-build)
Build log (run d8a6a027-214d-4b6e-89fb-358ff7b3d10e):
```
ERROR: Could not find a version that satisfies the requirement torch==2.15.0+cpu
  (from versions: 2.0.0 ... 2.14.1, 2.15.0)
ERROR: No matching distribution found for torch==2.15.0+cpu
```
Confirmed in source — `grep` of the pulled source:
```
/app/scratch/backend/requirements.txt:148:torch==2.15.0+cpu
```
- Plain `2.15.0` IS available on the index; the `+cpu` local-version label is not.
- `+cpu`-tagged wheels come only from the PyTorch CPU index (`https://download.pytorch.org/whl/cpu`), which is NOT configured in requirements.txt or the build (no `--extra-index-url` present), and those labeled wheels are not published for arm64 (this is an arm64 build) anyway.
- Both prior runs (d8a6a027, 56295aef) failed identically at this step.

**Fix (E1 / source):** Edit `backend/requirements.txt` line 148 to `torch==2.15.0` (drop the `+cpu` suffix). The arm64 PyPI wheel for 2.15.0 is already CPU-only, so this is the correct equivalent. Do NOT add an extra-index-url for `+cpu` — no such arm64 wheel exists.

### 2. Insufficient credits (trigger_indie)
```
insufficient_credits — Required: 50, Available: 49.503023359999986 (retryable: false)
```
This blocks the deploy from even starting a new run. I have no tool to add credits.

**Fix (User):** Top up the account credit balance (needs ≥ 50 ECU) so the deploy can be triggered.

## Not fixable by deployer agent
- The torch pin is user source → E1 must edit it (not a manifest issue).
- Credits → user account action.
- `resume_pipeline` was NOT called: it would be refused on credits, and even if funded, the build would still fail on the torch pin until it is corrected.

## Order of operations to recover
1. E1 fixes `backend/requirements.txt` line 148 → `torch==2.15.0`.
2. User adds credits (balance ≥ 50 ECU).
3. Redeploy.
