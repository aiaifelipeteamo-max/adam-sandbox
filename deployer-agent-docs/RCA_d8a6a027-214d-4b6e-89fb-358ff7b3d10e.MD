# RCA — Deploy run d8a6a027-214d-4b6e-89fb-358ff7b3d10e (adam-sandbox)

## Summary
The `build_image` step failed (backend-build 13/13, `pip install -r /app/backend/requirements.txt`). Root cause is a bad dependency pin in the app source — **not** a manifest, infra, or secret issue.

## Failing step
`build_image` → Cloud Build step #39 `[backend-build 13/13]`, exit code 1.

## Exact error
```
ERROR: Could not find a version that satisfies the requirement torch==2.15.0+cpu
 (from versions: 2.0.0, ... 2.14.0, 2.14.1, 2.15.0)
ERROR: No matching distribution found for torch==2.15.0+cpu
```

## Root cause (proven)
`/app/backend/requirements.txt` line **148** pins:
```
torch==2.15.0+cpu
```
The `+cpu` suffix is a **local-version variant** that is published only on the PyTorch CPU index (`https://download.pytorch.org/whl/cpu`), not on PyPI. The backend build installs from the default PyPI index with `pip install --no-cache-dir --no-dependencies`, which has no PyTorch extra-index configured, so `+cpu` cannot be resolved. pip's own list of candidates in the error tops out at plain `2.15.0`.

Evidence gathered in an isolated sandbox for this run:
- `grep -n torch /app/scratch/backend/requirements.txt` → `148:torch==2.15.0+cpu`
- torch is genuinely used by the app (`backend/neural.py` imports and uses `torch`), so it cannot simply be dropped.
- `pip index versions torch` on the build's index resolves fine to `torch (2.15.0)` with no `+cpu` tag available.

## Fix (E1 / code)
Edit `/app/backend/requirements.txt` line 148:
```
torch==2.15.0+cpu   →   torch==2.15.0
```
`torch==2.15.0` (plain) is confirmed available on the default index and installs the CPU build on this linux/arm64 image. After E1 applies this one-line change, redeploy.

(Alternative, only if a strict `+cpu` wheel is ever required: add `--extra-index-url https://download.pytorch.org/whl/cpu` to the pip install — but that would be a manifest change and is unnecessary here since the plain pin resolves.)

## Not the cause
Not a manifest fault, not a missing base-image tool, not a secret, not a tier/OOM issue. It is a wrong version string in the user's source dependency list.
