# RCA — Deploy run 56295aef-025a-43f3-a69d-9f1d95ea7e0b (adam-sandbox, initial deploy)

## Symptom
`build_image` step failed (Cloud Build, backend-build 13/13). Pipeline never reached deploy.

## Error (verbatim from build log)
```
ERROR: Could not find a version that satisfies the requirement torch==2.15.0+cpu
(from versions: 2.0.0, ... 2.14.0, 2.14.1, 2.15.0)
ERROR: No matching distribution found for torch==2.15.0+cpu
```
Failing command: `pip install --no-cache-dir --no-dependencies -r /app/backend/requirements.txt`

## Root cause (CONFIRMED + REPRODUCED)
`backend/requirements.txt` **line 148** pins:
```
torch==2.15.0+cpu
```
The `+cpu` suffix is a PyTorch *local version identifier* that is published ONLY on PyTorch's dedicated wheel index (`https://download.pytorch.org/whl/cpu`). It is NOT available on the default PyPI index that the build's `pip install` uses. PyPI hosts plain `torch==2.15.0` (no `+cpu` variant), so the pin cannot resolve and pip fails hard.

Reproduced in sandbox against the run's source:
- `pip install --dry-run 'torch==2.15.0+cpu'` → "No matching distribution found" (same error as the build).
- `pip install --dry-run 'torch==2.15.0'` → resolves cleanly: "Would install torch-2.15.0".

This is a source fault in the user's `requirements.txt`, not a manifest/platform/tier/secret issue.

## Fix (for E1 — edit source, then redeploy)
Edit `backend/requirements.txt` line 148. Choose one:

- **Simplest (recommended):** drop the local tag →
  ```
  torch==2.15.0
  ```
  The plain wheel resolves on the default index.
- **If a CPU-only build is specifically required:** keep `torch==2.15.0+cpu` but point the build at the PyTorch CPU index, e.g. add to the top of requirements.txt:
  ```
  --extra-index-url https://download.pytorch.org/whl/cpu
  torch==2.15.0+cpu
  ```
  (Also verify a matching `+cpu` wheel exists for the build arch — production builds are **arm64**.)
- **If torch isn't actually used** by the app, remove the line entirely.

After the source change, redeploy to re-run the pipeline.

## Notes
- Sandbox resolution ran on x86_64; the deployment builds on arm64. The failure is index-related (the `+cpu` local tag is absent from PyPI), not architecture-specific, so the diagnosis holds for arm64 as well. Plain `torch==2.15.0` publishes arm64 (manylinux aarch64) wheels.
